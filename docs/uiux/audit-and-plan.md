## 0. 怎麼測的

- `ng serve --port 4215`，三種尺寸走過每個畫面：iPad 直向 820×1180、iPad 橫向 1180×820、手機 390×844。
- 後端沒開，播放畫面用**暫時假歌詞**（自編句子，沒有 commit）。影片縮圖在截圖裡塗黑。
- 截圖：`docs/uiux/screens/`（`01`～`10`，檔名寫了畫面和尺寸）。
- 對比度用 WCAG 2.x 公式算；觸控目標用 `getBoundingClientRect()` 量。

**整體印象**：功能完整、版面乾淨、多數按鈕已經 ≥44px，`<dialog>`、`aria-live`、`aria-pressed` 都用得對，打底不錯。主要問題有三個：
1. **主色對比不夠**：白字配藍底只有 3.59:1。
2. **iPad 直向和手機上，小朋友「現在要做的事」被擠到畫面下面**。
3. **獎勵和回饋太安靜**：慶祝畫面是靜態的，貼紙只是一行字。

## 2. 設計 token（只用 CSS 自訂屬性，放在 `styles.css :root`）

原則：**保留舊的變數名**（`--accent`、`--muted`……），只改它們的值，所以現有的元件不用動，就會自動套用新顏色。新加的 token 給第二批使用。

| `--bg` | `#eaf6ff`（不變） | 頁面底色 | — |
| `--card` | `#ffffff` | 卡片 | — |
| `--ink` | `#16324f`（不變） | 主要文字 | 白底 13.1／`--bg` 上 11.9 |
| `--ink-2` 🆕 | `#53687e` | 次要文字、還沒唱到的歌詞 | 白底 5.75／`--bg` 上 5.24 |

| `--accent` | `#1769b8`（原本 `#2e8bdc`） | 主要按鈕的底、連結 | 白字 5.6 ✅（原本 3.59） |

### 2.2 字級（iPad 優先，7 歲閱讀：中文 ≥18px）

`--fs-xs 14px`（只給家長的註解）· `--fs-sm 16px` · `--fs-md 18px`（內文預設）· `--fs-lg 22px`（歌詞、題目）· `--fs-xl 28px`（頁標題）· `--fs-hero 64px`（emoji 頭像、慶祝）。
行高：內文 1.5，歌詞 2（同時撐大單字的點擊高度）。

### 2.3 間距、圓角、陰影

- 間距（4 的倍數）：`--sp-1 4px` · `--sp-2 8px` · `--sp-3 12px` · `--sp-4 16px` · `--sp-6 24px` · `--sp-8 32px`
- 圓角：`--r-sm 10px`（chip 以外的小元件）· `--r-md 14px`（按鈕）· `--r-lg 20px`（卡片、對話框）· `--r-pill 999px`（chip、播放鍵、麥克風鍵）
- 陰影：`--sh-1 0 2px 8px #16324f14`（卡片）· `--sh-2 0 6px 20px #16324f29`（按下、浮動視窗）
- 觸控：`--tap 48px`（一般）· `--tap-kid 64px`（播放、麥克風、選項）

### 2.4 元件規則

- **按鈕**：主要按鈕 = `--accent` 底配白字；次要按鈕（`.ghost`）= 白底、`--accent` 字、2px `--line-strong` 框。最小高度 `--tap`，小朋友的主要動作用 `--tap-kid`。`:active` 時 `scale(.97)`。停用狀態除了 `opacity .45`，再加 `cursor:not-allowed`。按鈕列用 `gap: var(--sp-2)`。
- **卡片**：`--card` 底、`--r-lg` 圓角、`--sh-1` 陰影、padding `--sp-4`。整張卡可以點的話，用 `<a>`／`<button>` 包起來，加 `:active` 回饋。
- **Chip**（單字）：`--r-pill` 圓角，高 44px，英文用 `--accent` 粗體，中文用 `--ink`。
- **對話框**：寬 `min(420px, 100% - 32px)`，`--r-lg` 圓角；標題 22px；動作按鈕放最下面、靠右，主要按鈕在右邊；一定要有可以聚焦的取消按鈕。
- **一個畫面只有一個「最大」的按鈕**，就是小朋友現在要按的那個。

## 3. 動態計畫（全部用 CSS，不加套件）

全域安全網（加在 `styles.css`）：
```css
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after { animation-duration: 1ms !important; animation-iteration-count: 1 !important; transition-duration: 1ms !important; scroll-behavior: auto !important; }
}
```
單一元件如果需要不同的降級方式，就在自己的 CSS 裡另外寫。

| 情境 | 一般 | reduced-motion | 時間 |
|---|---|---|---|
| 慶祝 | 星星 `scale(0)→1.2→1` 加旋轉 15°；12 片彩紙（`<i style="--i:n">`，`transform` 加 `opacity` 掉落，顏色輪流用 token）；按鈕 0.4 秒後淡入 | 星星直接出現，只做 `opacity` 淡入 | 共 1.2 秒，彩紙只播一次 |
| 答對（選項／唱過關） | 選項變綠，`scale 1→1.12→1`，右上冒出 ⭐ 往上飄 | 只變色，加 ✓ | 0.5 秒 |
| 答錯 | 左右輕晃 ±4px 兩次（現在是 6px），邊框變 `--warn`，顯示「再想想 🤔」 | 不晃，只變邊框加文字 | 0.3 秒 |
| 提示答案 | 跳 3 次後停住，外框加粗 | 外框加粗 | 3×0.6 秒 |
| 錄音中 | 麥克風鍵外圍的 `box-shadow` 光環擴散（循環，因為錄音中確實在持續） | 靜態 4px 光環 | 1.2 秒一圈 |
| 目前句換行 | 底色淡入 0.2 秒；捲動用 CSS `scroll-behavior: smooth`（現在寫死在 JS 的 `behavior:'smooth'` 要拿掉） | 立刻跳過去 | 0.2 秒 |
| 換頁 | Angular `withViewTransitions()` 加 `::view-transition-old/new(root)` 交叉淡入 0.2 秒（Safari 18 以上才有，沒有就直接換頁） | 不用轉場 | 0.2 秒 |
| 卡片／按鈕按下 | `:active scale(.97)` | 保留（不會造成暈眩） | 0.1 秒 |

**🔊 音效（要 PO 決定，見 Q1）**：用 Web Audio 的振盪器即時產生 3 種音：答對「叮」（兩個上升的音）、答錯「咚」（一個低音，不要刺耳）、慶祝（三和弦琶音）。**不用音檔、不加套件**。要在點擊的同步呼叫鏈裡建立或恢復 `AudioContext`（遵守 architecture §3 的 iOS 手勢規則）。家長設定裡放一個「音效：開／關」，存到 localStorage。

## 5. 需要 PO 決定的問題

1. **要加音效嗎？**（答對「叮」、答錯「咚」、慶祝琶音，用程式產生，不用音檔，家長可以關掉）
   → **建議：要，預設開。** 對 7–9 歲的小朋友，聲音回饋比視覺更即時；成本小（一個檔案、不加套件）。
2. **刪除小朋友的 ✕ 要藏起來嗎？**
   → **建議：藏在「✏️ 管理」按鈕後面**，按了才出現 ✕，再配合原本的確認視窗。比起「長按刪除」，這種做法更容易被找到，也不會讓小朋友誤觸。
3. **遊戲說明要拆成「小朋友版」和「家長版」嗎？**
   → **建議：拆。** 上面放 3 張圖示卡給小朋友看；表格收到 `<details>`「給家長看」裡面。內容不變，只是改排版。
4. **iPad 直向時影片要縮小嗎（約 38% 螢幕高）？**
   → **建議：要。** 歌詞和題目才是學習的主體，影片縮小後還是看得清楚。橫向版面不變。
5. **單字小視窗要停留多久？**（現在 3 秒自動關）
   → **建議：改成 6 秒，手指碰到就不自動關。** 7 歲小朋友讀中文加上聽發音，3 秒不夠。要改 `play-session.ts` 裡的一個數字（第三批，`ui-dialogs` 分支一起做）。
